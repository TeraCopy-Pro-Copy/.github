## Field Note

TeraCopy Pro is easier to trust when the queue stays smaller than the folder it came from. A named session shows which list is active, the pins show which copy queue you will run today, and the closing note tells the next person which pause resume drives the file transfer. That record is short on purpose: not a copy of every file, only the path back to the hash check that is still open on the reader's own folders.

The same loop fits a student lab packet, a client set you own, or a computer shared by two users. Open the last TeraCopy Pro session, confirm one copy queue, and leave the file transfer easier to follow than you found it. Other programs stay where they are. TeraCopy Pro only holds the copy queue, the hash check, and the handoff.

## One Real Pass

Pick a folder that already has a name and that you own: a short mixed set, a lab packet on your desk, or a thin working directory. Open it in TeraCopy Pro, keep only that queue on the board, and read one hash check you can point to. A pass is done when that check stays tied to the file transfer and the unused files are no longer in the way. TeraCopy Pro does not need a full rebuild of the working set before it is useful.

If the pass feels crowded, the queue is too wide. Drop anything that belongs to a different job and leave it out of this workspace. The next pass can have its own title. What matters is that this one stays readable from the first file to the last hash, with the summary still matching the pause resume on that PC.
